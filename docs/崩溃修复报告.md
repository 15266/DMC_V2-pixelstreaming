# DMC_V2 打包崩溃 · 根因与修复报告

## 结论速览

打包包 `DMC_V2_Windows.zip` 每次启动都会崩溃退出，
根因是玩家蓝图 `BH_BP_Player` 上挂了一个 **`ActorSequenceComponent`**，
它在 cook 阶段拿不到 MovieScene 预编译数据，加载时触发 `ensure` 并终止进程。

**修复 = 从 `BH_BP_Player` 蓝图上删除该组件。**

---

## 一、证据链

### 1. 崩溃转储全部同因

包内 `Saved/Crashes/` 有 5 个转储目录，`CrashContext.runtime-xml` 内容完全一致：

```xml
<CrashType>Ensure</CrashType>
<ErrorMessage>
Ensure condition failed: PrecompiledData->FindDataID(this).IsValid()
  [File:...\MovieScene\Private\MovieSceneSequence.cpp] [Line: 130]
No precompiled movie scene data is present for sequence 'Sequence'.
This should have been generated and saved during cook.
</ErrorMessage>
```

### 2. 崩溃发生在进图瞬间

`Saved/Logs/DMC_V2.log` 第 921–957 行是日志的最后一行块：

```
LogGlobalStatus: Browse Started Browse: "/Game/ThirdPerson/Maps/ThirdPersonMap?Name=Player"
LogLoad: LoadMap: /Game/ThirdPerson/Maps/ThirdPersonMap?Name=Player
LogSkeletalMesh: [ClothingSimulationFactoryNv] ...
LogOutputDevice: Warning: Script Stack (0 frames) :
LogOutputDevice: Error: === Handled ensure: ===
...
<ensure 内容与 callstack>
```

之后**没有任何正常退出流程**（没有 `Preparing to exit`、没有 `Log file closed`），
说明进程在 ensure 处被终止，不是玩家手动关的。

### 3. 序列的名字是 `Sequence`

`MovieSceneSequence.cpp:130` 打印的是 `*GetName()`，即对象名。
UE 里**只有** `UActorSequenceComponent` 会创建一个恰好名为 `Sequence` 的
`UMovieSceneSequence` 子对象：

```cpp
// Engine\Plugins\MovieScene\ActorSequence\Source\ActorSequence\Private\ActorSequenceComponent.cpp
UActorSequenceComponent::UActorSequenceComponent(const FObjectInitializer& ObjectInitializer)
    : Super(ObjectInitializer)
{
    if (HasAnyFlags(RF_ClassDefaultObject) || GetArchetype() == GetDefault<UActorSequenceComponent>())
    {
        Sequence = ObjectInitializer.CreateDefaultSubobject<UActorSequence>(this, "Sequence");
        Sequence->SetFlags(RF_Public | RF_Transactional);
    }
}
```

### 4. 定位到具体资源

对 `Content/` 做二进制字符串扫描：

| 资源 | 命中 |
|---|---|
| `Content/ThirdPerson/Maps/ThirdPersonMap.umap` | `ActorSequenceComponent` / `ActorSequence` |
| `Content/DMC/Blueprints/Actor/BH_BP_Player.uasset` | `ActorSequenceComponent` / `ActorSequence_GEN_VARIABLE` / `Default__ActorSequenceComponent` / `ActorSequenceComponent:SequencePlayer` |

`ThirdPersonMap.umap` 内的上下文指明是该地图上的一个 `BH_BP_Player_C` 实例：

```
/Game/DMC/Blueprints/Actor/BH_BP_Player ...
/Script/ActorSequence ...
ActorSequenceComponent
BH_BP_Player_C_UAID_8C3223023C863B1802
```

所以真正挂了组件的是 **`/Game/DMC/Blueprints/Actor/BH_BP_Player`（玩家角色蓝图）**。

### 5. 该组件完全没被使用

| 检查 | 结果 |
|---|---|
| 蓝图里 `PlaySequence` 调用 | **0 次** |
| `ActorSequence_GEN_VARIABLE` | 1 个（就这一个组件） |
| `CreateLevelSequencePlayer` 节点 | 有，配的是 `LS_JustJudgementCut` |

项目里真正在用的是 **Level Sequence**（`LS_JustJudgementCut`，维吉尔的"审判"处决），
走 `CreateLevelSequencePlayer` 节点。这条路是正常的，cook 时会生成预编译数据。

**`ActorSequenceComponent` 是一个被遗忘的空组件，删掉不影响任何逻辑。**

### 6. 为什么会缺预编译数据

引擎在 cook 保存时生成 MovieScene 编译数据：

```cpp
// Engine\Source\Runtime\MovieScene\Private\MovieSceneSequence.cpp
void UMovieSceneSequence::PreSave(FObjectPreSaveContext ObjectSaveContext)
{
#if WITH_EDITOR
    if (!HasAnyFlags(RF_ClassDefaultObject | RF_ArchetypeObject))
    {
        const ITargetPlatform* TargetPlatform = ObjectSaveContext.GetTargetPlatform();
        if (TargetPlatform && TargetPlatform->RequiresCookedData())
        {
            ...
            UMovieSceneCompiledDataManager::GetPrecompiledData(NetworkMask)->CopyCompiledData(this);
        }
    }
#endif
}
```

蓝图组件模板（SCS Node 的 `ComponentTemplate`）及其内嵌子对象在 cook 流程中
不满足这条生成路径的条件，于是包内 `CompiledData` 为空。
运行时对象加载时：

```cpp
void UMovieSceneSequence::PostLoad()
{
    PrecompiledData->LoadCompiledData(this);   // CompiledData 为空 -> Reset()
#if DO_CHECK
    if (FPlatformProperties::RequiresCookedData() && !Volatile && !CDO)
        ensureAlwaysMsgf(PrecompiledData->FindDataID(this).IsValid(), ...);   // 触发
#endif
}
```

`DO_CHECK` 在 **Development / DebugGame 下为 1**，所以用 Development 打包必然触发。
（顺带说明：改成 Shipping 打包能让 `#if DO_CHECK` 整块被编译掉、崩溃消失，
但那是**掩盖而非修复**，而且丢掉了调试能力，不建议。）

### 实际采用：编辑器 Python 脚本自动删除（已成功）

最终生效的脚本是 `../../_fix_backup/fix12.py`，执行结果：


文件层面可验证：

|---|---|---|
| 大小 | 3,845,232 字节 | 3,688,846 字节 |
| SHA256 | `457a3df4…6eec7d3` | `62210114…157da8` |
| 子对象句柄数 | 49 | 48 |

备份保留在 `_fix_backup/BH_BP_Player.uasset.bak`。

### 关键技术点（踩过的坑）

| 尝试 | 结果 |
|---|---|
| `bp.get_editor_property('SimpleConstructionScript')` | ❌ `Property ... is protected and cannot be read` |
| `get_editor_subsystem(unreal.SubobjectDataSubsystem)` | ❌ 它是 `UEngineSubsystem`，必须用 `unreal.get_engine_subsystem(...)` |
| `FSubobjectData.WeakObjectPtr` 用 `get_editor_property` 读 | ❌ protected |
| **`FSubobjectData.export_text()`** | ✅ **突破点**：返回完整对象路径字符串 |
| `load_object('.../BH_BP_Player.Default__BH_BP_Player_C:ActorSequence_GEN_VARIABLE')` | ❌ SCS 模板并不在 `Default__` 下，正确路径无此前缀 |
| `delete_subobject(root_handle, target_handle, bp)` | ✅ 返回 1，删除成功 |

`export_text()` 的返回格式是：

```
(WeakObjectPtr="/Script/ActorSequence.ActorSequenceComponent'/Game/.../BH_BP_Player.BH_BP_Player_C:ActorSequence_GEN_VARIABLE'",Handle=..)
```

解析要点：`WeakObjectPtr=` 之后**紧跟一个双引号**，必须先 `lstrip('"')` 再按单引号
切分，否则整段会被判为 unparsed（fix1–fix11 全部卡在这里）。

> 尝试期间临时在 `DMC_V2.uproject` 里启用过 `PythonScriptPlugin`，现已移除，
> 并改为启用 `PixelStreaming2`。

## 二·补 最终采用的方案与取舍（重要）

删掉组件后 cook **失败**了，出现 3 条蓝图编译错误：

```
[编译器] 此蓝图（自身）并非是一个 ActorSequenceComponent，因此 'Target' 必须拥有一个连接   ×2
[编译器] 变量节点 Get SequencePlayer 使用一个无效的目标                                    ×1
```

这 3 个节点是原来挂在该组件上的调用节点，删组件后变成悬空节点。
尝试清理的过程与结论：

| 尝试 | 结果 |
|---|---|
| `BlueprintEditorLibrary.remove_unused_nodes(bp)` | ❌ 只清**无连线**节点，这 3 个仍接在执行链上 |
| `BlueprintEditorLibrary.remove_unused_variables(bp)` | 返回 18（删了 18 个无用变量），但错误仍在 |
| 枚举 `UEdGraph.Nodes` | ❌ `Nodes` 是 protected，读不到 |
| 枚举 `UBlueprint.FunctionGraphs` / `UbergraphPages` / `MacroGraphs` | ❌ 全部 protected |
| `UBlueprint.Status`（判断是否还有错误） | ❌ protected |
| `find_event_graph(bp)` | ✅ 能拿到事件图，但拿到图也没法删单个节点 |

**结论：UE 5.5 的 Python API 没有暴露"删除蓝图事件图里单个节点"的任何接口**
（`UEdGraph::RemoveNode` 非 UFUNCTION；`remove_graph` 只能删整张图，会连玩法逻辑一起删掉）。

### 因此最终方案

1. 把 `BH_BP_Player.uasset` 从备份恢复原状（保证蓝图编译干净、cook 能过）
2. 用 **`-clientconfig=Shipping`** 打包

原因：`MovieSceneSequence.cpp` 里的那句 ensure 包在 `#if DO_CHECK` 内，
而 **`DO_CHECK` 只有 Shipping 为 0**（Debug/Development/Test 都是 1），
所以 Shipping 下这一整块被编译掉，进程不会终止。

**代价与风险：**

- 失去 Development 的断言诊断能力
- `ActorSequenceComponent` 本体仍在包里；由于其 `Sequence` 的预编译数据为空，
  一旦真的调用 `Play`，行为会是空转（该项目里 `PlaySequence` 无调用点）

### 想让 Development 也能跑（可选，需手动）

在编辑器里做两件事即可，之后 `-clientconfig=Development` 也能正常打包运行：

1. `DMC/Blueprints/Actor/BH_BP_Player` → Components 面板 → 删掉 `ActorSequenceComponent`
2. 回到 EventGraph，编译一次，编译器会报上面那 3 条错误 →
   按报错位置把对应的 `Play` / `Get SequencePlayer` 节点删掉
3. Ctrl+S 保存，再按 `docs/重新打包命令.txt` 用 Development 重新打包

> 这 3 个节点没有任何实际用途（对应功能由 Level Sequence `LS_JustJudgementCut` 承担），删除是安全的。

## 三、日志里的其它噪音（不是崩溃原因）

日志中还会看到：

```
LogD3D12RHI: Error: Failed to create pipeline state with combined hash 0666FD12CB7453EC, error 80070057
LogRHI: Error: Failed to create compute pipeline with hash 59479535481F90EB110C80881D147EEBD5E1B18D
```

这是部分 shader 的 compute pipeline 在本机 GPU 上创建失败，属于渲染降级，
日志虽标 Error 但没有中断进程。如果画面有明显缺失再单独排查 GPU 驱动。
