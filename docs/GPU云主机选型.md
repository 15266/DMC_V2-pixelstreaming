# DMC_V2 在线游玩 · GPU 云主机选型建议

前提：**Pixel Streaming 的服务端是一台带 NVIDIA/AMD 独显的 Windows 机器**，在上面原样运行 `DMC_V2.exe` 并把画面编码推流。
下面按"验证 → 小范围试用 → 正式对外"三档给建议。

---

## 一、为什么是 NVIDIA

DMC_V2 用的是 D3D12 + 大量 Niagara/VFX，**对 GPU 算力和显存带宽最敏感**。

像素流送的编码路径优先级为 **NVIDIA NVENC → AMD AMF → 软件编码(Vpx/VT)**。
软件编码会把 CPU 吃满，玩动作游戏必然掉帧，所以**必须选带独显的机型**。

本机当前环境（i7-8700 + 无独显）只能做"能跑起来"的验证，不能当串流服务端。

---

## 二、三档配置

### 第 0 档：零成本验证（你自己的机器）

| 项 | 建议 |
|---|---|
| 用途 | 只验证串流链路是否通、单人本机试玩 |
| 显卡 | 你现有的独显即可（GTX 1660 / RTX 3060 起） |
| 带宽 | 内网即可；跨公网需要 HTTPS + 域名 |
| 局限 | 延迟高、占用你本机资源、无法 7×24 |

如果只是想让别人看一眼效果，这档够了。

### 第 1 档：小范围试用（1–5 人）

| 项 | 建议 |
|---|---|
| 云厂商 | 腾讯云 CVM / 阿里云 ECS GPU 机型 |
| 候选实例 | 腾讯云 **GN7**（T4 16G）/ 阿里云 **gn7i**（A10 24G） |
| 系统盘 | 100 GB SSD；游戏包约 400 MB，镜像 + 日志留足空间 |
| 带宽 | **按固定带宽 10–20 Mbps 起**，务必确认上行能力 |
| 成本量级 | 约 ¥8–25 / 小时（按厂商活动浮动） |
| 说明 | 只做预约演示、收集反馈，随时开关机 |

### 第 2 档：正式对外（面向用户）

| 项 | 建议 |
|---|---|
| 实例 | 阿里云 **gn7i**（A10 24G）/ 腾讯云 **GN9**（T4）/ 或 L4、T4 |
| 数量 | 按并发数 1 实例 : 1–3 并发起步，压测后调整 |
| CPU | ≥ 8 核（编码与游戏逻辑分摊） |
| 内存 | ≥ 32 GB |
| 系统盘 / 数据盘 | 100 GB SSD |
| 带宽 | **固定带宽 ≥ 20 Mbps**，或按流量 + CDN 前的直连方案 |
| 安全组 | 放行 8888、80/443 |
| 成本量级 | ¥2–6 / 小时量级，需长期开机，务必评估月账单 |

> 上行带宽是像素流送体验的**第一瓶颈**：1080p60 大约需要 15–25 Mbps。
> 带宽不足时最先出现的不是掉帧，而是输入延迟飙升。

---

## 三、采购前必须确认的 4 件事

1. **Windows Server 2019/2022 或 Windows 10/11**（必须是 Windows；信令服务器本身跨平台，但游戏是 Win64）
2. **允许安装 NVIDIA 驱动**。部分 GPU 机型不带驱动镜像，需要能访问驱动源或使用厂商镜像
3. **公网带宽计费方式**。弹性公网 IP 的按流量计费在串流场景下会失控，建议固定带宽
4. **不用 Auto Scaling**。串流实例有会话状态，不能随便扩缩

---

## 四、更省事的替代路线：云电脑 / 远程串流

如果你只是想让朋友远程体验、且不追求低延迟，下面这些比自建像素流送更快落地：

| 方案 | 特点 | 适用 |
|---|---|---|
| 阿里云无影云电脑 | 有 Web 客户端，浏览器直接进 | 内部演示 |
| 青椒云 / 顺网云 | GPU 云桌面，按小时 | 小范围体验 |
| ToDesk / Parsec | 远程桌面串流，非浏览器 | 临时联调 |
| Steam Remote Play | 免费，但需 Steam 版本 | 自用 |

它们的**上限低于像素流送**：延迟更高、码率受限、浏览器内体验更差。
但零部署、零打包改动，适合"先让人看到东西"。

## 五、下一步

1. 先在第 0 档把链路跑通（修好崩溃 → 启用插件重打包 → 本机起信令 + 游戏 → 浏览器打开）
2. 链路确认无误后，再决定要不要租 GPU 机
3. 租机前先用第 1 档预约 1 小时验证公网表现与实际延迟

具体部署步骤见 `../README.md`。
